# AidFlow — 8 分鐘 Demo 腳本

> 事前：`docker compose up -d`，以系統管理者執行 `ADMIN_USERNAME=admin ADMIN_PASSWORD=… bash client/seed_demo.sh`，
> 並建立一個承辦審核人員帳號。建議電腦開後台（承辦帳號）、手機或無痕視窗開民眾端。

## 0. 一句話（15 秒）

> 「民眾看到災情，免登入就能通報；同一地點多人回報會自動成案並推播縣府 LINE 群組；承辦審核後，需要權責單位的上報 EMIC，小型災情開放民眾協助處理，處理進度都公開在地圖上。」

## 1. 民眾端（1.5 分鐘）

1. 首頁 `/`：大大的「我要通報災情」與開放中的災害事件。
2. `/p/{slug}`：狀態列（目前災情／審核中／處理中／民眾可協助）、地圖上的案件標竿、右側最新災情；「資料圖層」可自行開關雷達、土石流潛勢等政府開放資料。

## 2. 兩人成案（2 分鐘）

3. 手機 `/p/{slug}/report`：選「道路坍方」→ GPS 定位 → 拍照 → 勾選「接收案件處理進度」填 Email → 送出。
   - 回應：「縣府承辦人員已收到通知，同一地點再 1 位民眾回報會自動成案」。
4. 另一台裝置在 100 公尺內送「道路中斷」→「已成案，承辦人員正在審核處理方式」。
5. 後台「LINE 通知」分頁：看到「新通報」「待審核」兩筆通知（未設定 LINE 金鑰時標示模擬）。

## 3. 審核分流（2.5 分鐘）

6. 平台後台 `/console/platforms/{id}`：上方四張嚴重程度卡（極高／高／中／低）與「待審核」卡；右側「待審核」依嚴重度排序。
7. 開啟剛成案的坍方案件 → 檢視回報與照片 → 按「上報 EMIC」。
   - 說明：EMIC 規格尚未提供，採人工登錄；回填 EMIC 案號（內部）、處理狀態與處理單位（公開）。
8. 「儲存並改為處理中」→ 手機案件頁出現「EMIC 處理狀態：已派員處理」。
9. 另開「埔里鎮倒木」→「民間可處理」。

## 4. 民眾協助與結案（1.5 分鐘）

10. 手機開倒木案件頁 →「我來協助處理」→ 上傳處理後照片 → 送出。
11. 後台「待確認完成」+1 → 開啟案件看照片 →「確認通過・結案」。
12. 民眾地圖上這件災情消失；訂閱者收到「已結案」通知信。

## 5. 收尾（30 秒）

- 系統管理者：`/console/new` 輸入「115 年 0915 颱風豪雨」，災害類型自動勾選，右側預覽通報類別與圖層——不經 AI。
- 業務主管：「稽核紀錄」看得到誰在何時查閱了哪件案件的個資。
- 縣府網站：「複製嵌入地圖語法」貼到網站即可顯示同一張災情地圖。
